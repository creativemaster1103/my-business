# The modular framework — how a script is built

House messaging structure. Every UGC script is **assembled from blocks**, and each beat is
labelled with the block it is doing. Source: the `brook-adblock-analyzer` skill — load it rather
than working from this summary, and never invent a block that is not in it.

The same framework the swipe pipeline uses to *analyse* a competitor ad, used here to *build* one.
That symmetry is the point: a script written in blocks can be audited in blocks, and a winner can
be broken down and recombined.

## The blocks

**Structure blocks** — the skeleton, always all three:

| Block | Job |
|---|---|
| **Hook** (0–3s) | Pattern interrupt, curiosity gap, or a relatable problem |
| **Body** | Builds desire, handles objections, demonstrates |
| **CTA** | Drives one specific action |

**Product blocks** — how the offering is shown: Product Introduction · Demonstration ·
Features/Benefits · Buying Experience · Unboxing.

**Person blocks** — emotional connection and proof: Problem Statement · Failed Alternative ·
Desired Result · Before & After · Social Proof · Storytelling.

## How to use it when writing

1. **Choose the block sequence before writing a line.** Write it out as a flow first —
   `Hook → Failed Alternative → Problem Statement → Product Introduction → Demonstration →
   Desired Result → CTA`. If the sequence does not make sense on its own, no amount of good
   phrasing will save the script.
2. **One block per beat.** A beat trying to do Problem Statement *and* Social Proof does neither.
3. **Label every beat in the brief**, inline in yellow, so the editor and the strategist can see
   the structure: `<span color="yellow">PERSON BLOCK: Failed Alternative …</span>`.
4. **Name the angle** from the framework's Ad Angles table — Problem-Solution, Comparison,
   Transformation, Identity, Social Proof, Authority, Curiosity/Secret, Scarcity, Origin/Founder,
   Education/How-To, Trend, Functional Benefit, Gifting. **One dominant angle**, not three.
   It is a gate: the user sets it, you recommend.
5. **The two scripts on a page should use different sequences**, not just different words. Two
   scripts that both run Problem Statement → Product Introduction → Desired Result are one script.

## Blocks that do not transfer to us

- **Social Proof** — a creator citing reviews or user counts is a claim the brand owns, and the
  compliance gate blocks unsourced numbers. Use it only with an approved, sourced figure.
- **Before & After** — allowed only as a *situational* contrast ("the dinner, the drive home"),
  never as a health outcome. A before/after framed as symptom change is a condition claim.
- **Buying Experience** — no price in the script while Shopify is on hold. Guarantee language
  needs the current window confirmed before it can be cited.
- **Unboxing** — fine, but it is a different shoot from these ten clips.

## The launch line

**Hoolest Mini is a new product.** Every script carries a launch beat at **Product Introduction**:

> *"Hoolest just launched their newest vagus nerve stimulator."*

Then the product intro proper. Rules:

- It goes **at Product Introduction**, never in the hook. The hook is the viewer's problem, not
  the brand's news — a launch announcement as a hook is an ad announcing itself.
- **"Vagus nerve stimulator" / "vagus nerve stimulation device" is approved language.** Targeting
  the vagus nerve is on the approved claim list; what the device *does for a condition* is not.
- Keep it to one sentence and keep it in the creator's register. "Hoolest just launched their
  newest one" beats "introducing the all-new Hoolest Mini."
- **Drop it once the launch is over.** This is a launch-window beat, not a permanent fixture —
  when Event stops being `Launch`, this line goes.
